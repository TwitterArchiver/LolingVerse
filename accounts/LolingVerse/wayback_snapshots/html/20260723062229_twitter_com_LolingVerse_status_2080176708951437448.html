### DNSSEC 到底防什么
DNSSEC（DNS Security Extensions）通过数字签名给 DNS 记录加上“防伪标签”。
它保证的是：**你拿到的 A/AAAA 记录确实是域名所有者签过名的，中途没被篡改**。

所以针对**运营商 DNS 劫持**（运营商递归解析器直接返回假 IP）：

| 场景 | DNSSEC 是否有效 | 说明 |
|------|----------------|------|
| 域名**已启用 DNSSEC** + 客户端**本地验证** | ✅ 有效 | 假响应没有合法签名，会被直接拒绝 |
| 域名已启用 DNSSEC + 只信任运营商递归解析器 | ❌ 基本无效 | 运营商可以返回“无签名”的假记录，客户端照单全收 |
| 域名**没启用 DNSSEC** | ❌ 完全无效 | 没有签名可验证 |
| 运营商做的是 HTTP/HTTPS 层劫持或 IP 路由劫持 | ❌ 无效 | DNSSEC 只管 DNS，不管后面 |

### 实际要生效需要满足两点
1. **域名本身必须签了 DNSSEC**（在注册商那里开启，并正确配置 DS 记录）。
很多个人/家宽自建站根本没开。
2. **客户端必须自己做验证**，而不是把信任全部交给运营商的 DNS。
- Windows：需要额外配置（或用 Unbound、Acrylic 等本地验证器）
- Linux/macOS：systemd-resolved、Unbound 等可以开 `DNSSEC=yes`
- 浏览器/系统默认行为大多是“信任递归解析器”，不会严格本地验证

### 更实用的防护组合（推荐）
光靠 DNSSEC 在国内运营商环境下经常不够，建议叠加：

- **用加密 DNS（DoH/DoT）指向可信解析器**
Cloudflare 1.1.1.1、Google 8.8.8.8、Quad9、阿里 DoH 等。
这些解析器会自己做 DNSSEC 验证，而且查询内容运营商看不到、也改不了。
- 客户端开启本地 DNSSEC 验证（如果用自建 Unbound 等）。
- 重要站点尽量用 HTTPS + HSTS，即使 DNS 被骗，证书也会对不上（但诈骗站现在也会上假证书，只能降低成功率）。

### 总结
DNSSEC **理论上可以防运营商 DNS 劫持**，前提是域名签了名 + 客户端验证。
现实中大部分家宽自建站和普通用户都不满足这两个条件，所以单独开 DNSSEC 作用有限。
真正有效的是：**加密 DNS（DoH/DoT）+ 可信解析器**，DNSSEC 作为额外一层完整性保护会更好。
